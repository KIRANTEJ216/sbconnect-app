SB Connect is a member-only business networking web application. What This Web Application Is About

SB Connect is designed for a structured business community or membership organization. The product brings together directory discovery, opportunity sharing, meeting participation, and admin-led membership governance in one responsive web app.

The application is not a public marketing website. It is an operational member portal. The first useful experience after authentication is the dashboard, where a member can see membership status, browse directory counts, review requests, record business given, check the leaderboard, view meeting updates, and act on attendance prompts.

Primary User Workflows

Member onboarding

1. RegisterCreate account using name, phone, email, and password.
2. Sign inUse email or registered phone number plus password.
3. Create profileFill business details, categories, keywords, photo, catalog, and contact details.
4. Await verificationProfile is visible with pending status until admin approval.
5. Use portalBrowse directory, post requests, RSVP, attend meetings, and record deals.

Opportunity workflow

1. Post requestMember creates a requirement with category, budget, and deadline.
2. Browse requestsOthers filter by category and inspect details.
3. Express interestInterested members send a pitch and phone contact.
4. Award contractOwner/admin selects a participant and closes the request.
5. Track valueDeal record feeds stats and leaderboard.

Controls Implemented

Form and data controls

  • Text inputs for login, registration, company details, phone, email, website, amount, and search.
  • Password inputs and confirm password validation.
  • Textarea controls for company description, request description, and interest messages.
  • Select dropdowns for business size, membership status, deal receiver, and award receiver.
  • Date inputs for deadlines, meeting dates, and membership expiry editing.

  • Multi-select category buttons and keyword chips.
  • Client-side validation for required fields, file types, file size, duplicate interest, and profile edit limits.

Interaction and navigation controls

  • Responsive sidebar, mobile sidebar, and bottom navigation.
  • Primary, outline, danger, ghost, and loading button states.
  • Clickable cards for profile, request, dashboard stat, and chat navigation.
  • Category filter pills for request browsing.
  • Collapsible admin sections.
  • Confirmation dialogs for destructive request and meeting actions.
  • CSV export buttons for membership payments and directory data.
  • QR code generation for profile links and meeting attendance scan links.
  • Status badges for verified, pending, active, expired, open, closed, awarded, present, and unread states.

Security And Governance Observations

Important: the app has meaningful client-side role checks and Firestore helper checks, but production safety depends on Firestore and Storage rules. Admin operations, profile edits, request deletion, attendance writes, and file uploads should be protected in Firebase rules, not only in React code.

Strengths

  • Role model includes user, admin, and super_admin.
  • AdminGuard protects the admin route.
  • Sensitive helper functions call requireAdmin.
  • Duplicate pitch and duplicate attendance prevention exist.
  • File type and size validation exist before upload.

Risks to verify

  • Client-side admin access code could be abused if rules allow role self-updates.
  • Attendance marking should verify valid meeting IDs and active meeting state in rules or Cloud Functions.
  • Deal amount parsing is flexible but may need normalized numeric storage.
  • Chat cleanup currently depends on client activity rather than scheduled backend cleanup.

Suggestions And Improvements

1. Move sensitive workflows to Cloud Functions

Admin role changes, attendance scan validation, deal awarding, membership renewal, and future payment confirmation should be server-side functions with strict authorization.

2. Complete Razorpay membership payments

Add payment order creation, webhook verification, invoice/receipt storage, automatic membership date and expiry updates, and admin payment reconciliation.

3. Normalize money and dates

Store deal amounts as numeric paise/cents or integer INR units, keep display formatting separate, and use server timestamps for auditable records.

4. Strengthen attendance compliance

Bind QR codes to active meetings, prevent stale QR usage, optionally add geolocation or admin scan mode, and calculate compliance with scheduled backend jobs.

5. Add admin analytics

Include charts for new members, verified vs pending profiles, meeting attendance trends, RSVP conversion, request closure rates, deal value, and inactive members.

6. Improve messaging readiness

Add participant names/photos when conversations are created, backend retention cleanup, abuse reporting, and optional push/email notifications for unread messages.

7. Add test coverage

Prioritize tests around auth redirects, profile creation, request pitching, duplicate prevention, admin permissions, attendance scan behavior, and membership expiry.

Conclusion

SB Connect is already a practical MVP for a business membership network. Its strongest areas are member directory, request marketplace, meeting attendance, profile governance, and admin operations. The next major product step should be turning admin-critical and money-related actions into server-validated workflows, then completing payments and analytics.
